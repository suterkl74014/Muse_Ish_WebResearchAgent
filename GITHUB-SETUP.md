## First release

Create a GitHub release/tag named:

```text
v0.3.9.4
```

Suggested title:

```text
WebAgent v0.3.9.4 — Human Verification Handoff
```

Suggested summary:

> WebAgent is an MIT-licensed visible-browser AI agent for Windows. v0.3.9.4 adds safe human-verification handoff: when a CAPTCHA or verification challenge appears, automation pauses, foregrounds Chromium, waits for the user to complete it, then resumes after the page is clean.

## Make the repo easier to discover

1. Add a real screenshot near the top of `README.md` once you have one.
2. Record a 15–30 second GIF showing: prompt → task plan → visible browser → artifact.
3. Keep the first README screen focused on what the project does, not implementation history.
4. Turn on GitHub **Discussions** if you want workflow/showcase posts separate from issues.
5. Turn on **Private vulnerability reporting** under repository security settings.
6. Pin a “Show what you built” discussion when community activity starts.
7. Use releases/tags for meaningful versions so people can follow progress.
8. Keep screenshots free of API keys, personal accounts, addresses, cookies, or private browser content.

## Good demo prompts

Use only public/non-sensitive sites when recording demos.

```text
Research three open-source browser automation frameworks, compare their strengths,
and create a Markdown decision matrix with sources.
```

```text
Research a technical topic across several sources and create a concise PDF briefing.
```

The best GitHub demos show a concrete result, visible progress, and user control—not just a chat response.
